## 引用の順位を比較した結果

変更前と同じキャッシュを使い、「性質」「その他」の節ごとに、今回の解説を直接裏付ける引用が何番目に出るかを調べた。対象29ページで該当したのは3ページの4件だった。

| 数字と話題 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 89のフィボナッチ級数 | 1位 | 1位 |
| 89の逆数の十進展開 | 2位 | 2位 |
| 74シリーズの標準ロジックIC | 2位 | 2位（1位は既存の「永久欠番」ピン） |
| NE555タイマIC | 8位 | 1位 |

関連する4件のうち上位3件に入るものは3件から4件になった。加点は対象の数字・節・話題が一致したときに30点とし、同じ候補への加点が重なる場合は最大値を使う。配布用ページでは555の順序だけが変わり、全1,189ページで引用文と出典は変更前と一致した。残る26ページの補足には、数学の原論文やメーカー資料などの出典を掲載した。

新規取得も別に検証した。日本語版Wikipediaの144と555の該当節をそれぞれ一度取得し、同じ原文と同じ知名度の推定条件で加点だけを切り替えた。144のフィボナッチ平方数は取得候補10位から1位、最終選定は1位のまま。555のタイマICは候補9位から1位、最終選定は3位から1位になった。この比較は2記事の該当節を対象としたもので、全記事の検索精度を推定するものではない。[144の性質](https://ja.wikipedia.org/wiki/144#性質)・[555のその他](https://ja.wikipedia.org/wiki/555#その他)

## 影響範囲と検証

- 数学・科学・文化・実数の生成元は `tools/number_math_notes_v1.json`、`tools/science_notes_v1.json`、`tools/number_lore_v1.json`、`tools/real_constants_v1.json`。数字列の展開時にも `tools/real_digit_notes.py` が Issue 番号を引き継ぐ。
- 引用の採点は `tools/wikipedia_ja.py`、設定は `tools/wikipedia_ja_importance_overrides_v1.json`。採用済みキャッシュには元の点数がないので、`tools/generate_numbers.py` は手動ピンを先頭に置き、加点の等しい引用の元の順番を保つ。
- 検索の変更は `tools/build_viewer_index.py`、`assets/app.js`、`index.html`。サンプル6件の確認後、Wikipediaの節を含めて全1,189ページと索引を再生成した。個別ページの差分は対象29ページ。索引・README・AGENTS.mdにも反映した。
- Python の回帰検査は `tools/test_issue_lore.py` と `tools/test_wikipedia_issue_weights.py` を含む33件が成功。内部リンク11,712件でリンク切れ0件、フィルタ定義94種で不整合0件だった。引用7,218件中の数式5,938件と今回追加した51式はKaTeX 0.16.11で検査し、エラーは0件だった。
- Chromeで `#8 SRAM` が62だけを返すこと、未知の番号、フィルタの併用と解除、数字間のリンク、幅320pxの表示を確認した。
